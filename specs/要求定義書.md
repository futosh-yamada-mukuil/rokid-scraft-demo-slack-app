# 要求定義書

## 1. 目的

Rokid Glassesを装着した現場作業者が、写真と任意の音声コメントを遠隔の担当者へ共有し、返信を字幕と音声で受け取れる展示会デモを提供する。

基本の共有先はMicrosoft Teamsとする。展示・開発・多言語検証用として、同一LAN上のPCモニターへ送る経路も提供し、端末設定で排他的に切り替える。

## 2. 利用者

- 現場作業者: Rokid／Androidを操作し、撮影・送信・返信確認を行う
- 遠隔担当者: TeamsクライアントまたはPreactモニターで内容を確認し、返信する
- 展示運用者: 接続先、言語、認証、APIキーを準備する

## 4. 宛先選択

- Teamsのテナント、クライアント、チーム、チャネルが揃う場合はTeamsとモニタを候補に出す。
- Teams設定済みの初期状態ではTeamsを基本の宛先とする。
- Teams未設定時はモニタだけを表示する。
- 送信は選択した1宛先だけに行い、TeamsとPCへ同時送信しない。
- 「動画を撮る」は準備中の無効項目として表示する。
- 撮影画面のスワイプでは送信先を変更しない。
- 写真撮影時に縦／横を選ぶ。解像度は端末で利用可能な最大値を使う。
- Feedと新着通知の取得元は、設定画面に保存された既定送信先に合わせる。

## 5. Teams要件

- Microsoft GraphのDevice Code Flowを使用する。
- 権限はChannelMessage.Read.All、ChannelMessage.Send、offline_accessに限定する。
- アクセストークンとリフレッシュトークンを端末で暗号化保存し、期限前に更新する。
- 指定された1つのチーム／チャネルだけを画面上の対象とする。
- ロビーは撮影送信先と独立してTeamsチャネルを定期取得し、新着を通知音・HUD・TTSで知らせる。
- ロビーの操作メニューを可視領域上部へ置き、動画項目は準備中として無効にする。未認証時はデバイスコード画面、通信失敗時は再試行を提示する。
- 写真はhostedContentsとして本文へ埋め込む。
- 動画、投稿の編集、投稿の削除は対象外とする。

## 6. PCモニター要件

- 端末とPCは相互到達できる同一LANに接続する。
- 端末別IDと共有トークンでアップロードと返信を識別・保護する。
- Geminiで音声言語を自動判定し、PC表示は日本語とする。
- 返信先言語は受信時の端末設定（ja、en、nl）とする。
- Gemini障害時もメディア自体は保存する。
- 返信翻訳に失敗した場合、未翻訳の返信を端末へ送らない。

## 7. 非機能要件

- Rokid Glasses（Android 12／API 32）で動作する。
- タッチパッドの前後スワイプ、タップ、ダブルタップで主要操作を完結する。
- 画面消灯・バックグラウンド時はポーリングを停止する。
- Rokidで見える画面上側約2/3に合わせ、文字と操作を画面高さの64%以内へ収める。
- APIキー、Teamsトークン、共有トークンをGitへ保存しない。
- デモ途中の外部API失敗で撮影データや下書きを即時破棄しない。
- LEDは一般アプリから制御できないため、音とHUD表示で代替する。

## 8. 未完了・制約

- PreactのTeamsチャットモーダルはコード上にあるが、現在の画面導線には未接続。
- PC表示言語は日本語固定。
- TTSの有効／無効切替は未実装。
- 同一LANの最終確認とRokid実機での多言語往復確認が必要。
