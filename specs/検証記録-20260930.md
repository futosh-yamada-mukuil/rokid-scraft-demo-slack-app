# 機能検証記録（2026-09-30）

## 検証範囲と結論

現在有効な機能について、Googleの実API、Android arm64エミュレーター、PCの実HTTP、Microsoft Graphの実読取、回帰テストで経路を確認した。Google STT・TTS・Cloud Translationは共通の `GOOGLE_STT_TTS_TRANSLATE_API_KEY` を使用する。クラウド中継は設置していない。

Rokid実機は今回ADBに接続されておらず、最新版の実機導入、実マイクの認識精度、実視界の見切れ、実スワイプ、バックグラウンドの音声出力は未確認。Teamsへの実投稿は利用者の指示により実施していない。これらを「実機で全機能確認済み」とは扱わない。

動画撮影・Teams動画投稿は、利用者が指定した準備中／disabledの仕様を維持する。今回の完了対象に含めない。

最終回帰テストはAndroid 390件、API 52件、Web 58件の計500件。失敗・スキップなし。APKビルド、Web本番ビルド、Android Lint／ktlint、API／Webの型チェックも成功した。

## オフラインモデルの選定

Whisper tinyとbaseは同じ日本語音声で「写真」が欠落した。SenseVoice AUTOに前後250msの無音を加えた構成は日中英韓の期待文に一致したため変更した。日本語の単語間空白は除去し、韓国語は認識結果の語間空白を保持する。

Android arm64エミュレーターでの測定（モデルのロード・解放を含む）:

| 入力 | 所要時間 |
|---|---:|
| 日本語 | 4,168ms |
| 英語 | 3,072ms |
| 中国語 | 2,508ms |
| 韓国語 | 2,334ms |

300ms間隔のdumpsys測定でピークPSSは404,868KiB（約395MiB）、解放後は約152〜160MB。カメラを閉じて認識し、処理の重複を防ぎ、低メモリ／600MiB未満の空きではエラーを返す。Rokidの速度と空きメモリは実機接続後に測定する。APKは約307MiB。モデル、実行ライブラリ、ライセンスはダウンロード固定値・SHA256で管理する。

## 再検証

```sh
bash scripts/fetch-offline-stt.sh
node scripts/verify-google-services.mjs /path/to/.env .local/google-verification
node --experimental-strip-types scripts/verify-monitor-services.mjs . /path/to/.env .local/google-verification
```

上記はダミー音声・ダミー画像のみを使用する。モニタ検証ではTeams設定を渡さず、実投稿できない構成にしている。キー値は出力・保存しない。

Android検証は `:rokid:assembleDebugAndroidTest -PinstrumentationRunner=<クラス名>` で対象のrunnerを選び、APKとテストAPKを導入して `adb shell am instrument -w com.scraft.glassreport.test/<クラス名>` を実行する。

- `com.scraft.glassreport.capture.asr.GoogleServicesDeviceTest`: APKの実Google 3サービス（日中英韓／翻訳16組）。明示実行時だけAPIに通信する。
- `com.scraft.glassreport.capture.asr.OfflineSttDeviceTest`: 実オフラインJNIで4期待文の一致を判定。
- `com.scraft.glassreport.capture.camera.PhotoWatermarkDeviceTest`: 生成画像によるクロップ・ロゴの画素検証。

音声runnerはアプリの `files/offline-stt-test/{ja,en,zh,ko}.wav` を読む。`verify-google-services.mjs` が生成する中国語ファイル `zh-CN.wav` は `zh.wav` としてコピーする。期待文はrunnerに記載する。

エミュレーターの通常DNSでGoogle名の解決が失敗したため、APKのGoogle検証に限ってPC上の一時HTTPS CONNECT経路を使用した。TLSはGoogleまで終端せず、製品コード・キー・API要求は変えていない。製品へ中継処理やDNSの代替設定は追加していない。実機の通常ネットワークは別途確認が必要。

通常のAndroid終了後のTeams通知は常駐サービス／30秒ポーリングの設計。OSによる強制停止・端末電源断で動き続けることは前提にしない。
