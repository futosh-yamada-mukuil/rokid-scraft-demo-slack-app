# 全体アーキテクチャ図

## 構成

    Rokid / Android
      ├─ ロビー: Teamsチャネルの会話表示、新着HUD・Blow通知音・TTS
      ├─ 設定: 既定送信先 = Teams / モニタ
      ├─ Teams選択
      │    ├─ Entra ID: Device Code Flow
      │    └─ Microsoft Graph: 写真＋文字起こしコメント送信、チャネル取得
      ├─ モニタ選択
      │    └─ Fastify API
      │         ├─ uploads / replies
      │         ├─ Google STT: PC音声入力のAUTO認識
      │         ├─ Cloud Translation: PCからの返信翻訳
      │         └─ Preact: 表示・返信・設定QR
      ├─ Google Cloud TTS: 返信読み上げ
      └─ コメントSTT: Google STT / 同梱SenseVoice（設定切替）

## レイヤー

| レイヤー | 主な実装 | 責務 |
|---|---|---|
| UI | feature配下 | 画面、タッチ操作、状態表示 |
| ドメイン | domain配下 | Feed、画質、翻訳などのモデル |
| 端末I/O | capture、core配下 | CameraX、録音、通知音、TTS |
| Android通信 | net/teams、net/devmonitor | GraphまたはPC APIとの通信 |
| PC API | app/api/src | 保存、翻訳、返信、Teams復旧API |
| Web | app/web/src | 一覧、ビューア、返信、設定QR |
| 契約 | app/shared/src | APIとWebの型 |

## 設計方針

- 送信先はMediaSinkで抽象化し、撮影処理からTeams／PCの違いを分離する。
- TeamsとPCへの同時送信は行わない。
- Teams設定済みならTeamsを基本とし、未設定ならPCだけを候補にする。
- 撮影はメモリ安定性を優先して上限2048×1536以内の対応解像度を使い、写真の縦／横4:3を選ぶ。送信先固有の画像処理はDI層へ閉じる。
- Feedも既定の送信先に合わせてTeamsFeedRepositoryとLocalReplyFeedRepositoryを切り替える。
- ロビーの会話一覧は送信先にかかわらずTeamsFeedRepositoryを使う。返信HUDは選択送信先のTeams／PCを監視する。動画メニューは準備中で無効。
- 外部APIの認証情報はソースコードとGitへ置かない。
