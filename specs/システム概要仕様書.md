# システム概要仕様書

## 1. 概要

本システムはRokid／Android、Microsoft Teams、PC上のFastify APIとPreactモニターで構成する。基本経路はTeamsであり、設定によりPCモニター経路へ切り替える。

## 2. コンポーネント

| コンポーネント | 役割 |
|---|---|
| Rokidアプリ | 写真撮影、任意の5秒録音、Teams会話ロビー、宛先設定、Teams認証、字幕、TTS |
| Microsoft Entra ID | Device Code Flowとトークン更新 |
| Microsoft Graph | Teamsチャネルへの投稿とメッセージ取得 |
| Fastify API | PC経路の受信、保存、翻訳、返信キュー、SSE |
| Gemini API | PC経路のAUTO文字起こしと日・英・蘭翻訳 |
| Preactモニター | 写真・動画・翻訳の表示、テキスト／音声返信、設定QR |
| Google Cloud TTS | Rokid上のクラウド音声合成 |
| AmiVoice | Teams経路用の端末側音声認識機能 |

## 3. Teams経路

1. 設定画面で既定の送信先をTeamsにする。
2. 未認証の場合はRokidにデバイスコードを表示する。
3. 別端末でMicrosoftのデバイスログイン画面を開き、コードを入力する。
4. Rokidで写真の縦／横を選んで撮影する。コメントを残す場合だけ5秒録音し文字起こしする。
5. 確認画面にTeamsと表示し、承認後にMicrosoft Graphへ送信する。
6. PC／タブレットのTeamsクライアントで投稿を確認・返信する。
7. Rokidのロビーは送信先設定に関係なくTeamsチャネルの会話を表示する。新着はHUD・Blow通知音・TTSで知らせる。

ロビーのTeams取得で未認証が判明した場合はデバイスコード画面へ一度だけ遷移し、戻った後の再認証はロビーの操作から行う。通信失敗時は理由と「再試行」を表示し、即時再取得できる。実機の表示領域は上端から約2/3のため、共通UIの文字と操作は高さ64%以内に置く。

写真は撮影時に端末で利用可能な最大解像度を使い、Teams投稿時の画像サイズは送信処理で調整する。撮影コメントの翻訳はしない。動画の入口は準備中として無効化する。

## 4. PCモニター経路

1. PCでFastify APIとPreactを起動する。
2. 設定QRでPCのLAN URL、共有トークン、端末言語をRokidへ渡す。
3. 設定画面で既定の送信先をモニタにする。
4. Rokidから写真と任意の音声コメントをmultipartで送る。
5. 撮影コメントは端末で文字起こしし、APIでは翻訳しない。
6. APIがメディアとメタデータを保存し、SSEでPreactへ通知する。
7. PC担当者が日本語テキストまたはマイク音声で返信する。
8. APIが端末言語へ翻訳し、端末ID別の返信キューへ保存する。
9. Rokidが返信を取得し、HUD字幕とGoogle Cloud TTSで通知する。

## 5. 宛先と受信元の関係

設定画面の「既定の送信先」は撮影時の宛先とFeedの取得元を決定する。ロビーの会話とロビー表示中の新着通知は常にTeamsチャネルを参照する。

| 既定値 | 撮影送信 | Feed／ロビー以外の通知 | ロビー |
|---|---|---|---|
| Teams | Graphの指定チャネル | 同じTeamsチャネル | Teamsチャネル |
| モニタ | Fastifyの/upload | 端末別ローカル返信キュー | Teamsチャネル |

撮影画面のスワイプで宛先は変更しない。

## 6. 保存

- Teams経路の記録本体はTeamsチャネルに置く。
- TeamsトークンはAndroidのEncryptedSharedPreferencesへ保存する。
- PC経路のメディアとメタデータはapp/api/uploadsへ保存する。
- PC経路の返信はapp/api/repliesへ端末別に保存する。
- PC経路の共有トークンとAPI側TeamsトークンはGit管理外のローカルファイルへ保存する。

## 7. ネットワーク

- Teams経路: RokidからMicrosoft Entra ID／GraphへHTTPS接続できること。
- PC経路: RokidとPCが同一LAN上で相互到達できること。APIは0.0.0.0:8787で待ち受ける。
- 開発用Androidではadb reverseでPC APIへ接続できる。
